Cache read ratio = cache reads ÷ (uncached input + cache reads + cache writes), over the arm's summed tokens. A low ratio is a reason to look, not a failure: a first request or a short session reads little however well it caches. First requests are each run's first request: what they write is a cold prefix, which depends on what ran before them, not on routing. After a change counts the requests whose model or effort differs from the request before them in the same loop: what switching did to the cache. A single-turn task never switches mid-conversation unless it escalates. Cut at the output cap counts requests that stopped at max_tokens, which is not a failed task: "still passed" counts the runs that recovered. Effort is what the session asked for before the router and what was sent; runs made before efforts were logged show "not logged".
