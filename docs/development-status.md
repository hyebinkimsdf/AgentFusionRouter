# 개발 진행 현황

**기준일: 2026-10-30 · 버전: 0.1.0, 정식 배포 전**

이 문서는 현재 저장소의 구현 범위, 확인한 검증 결과, 다음 개발 단계를 정리합니다. 제품 소개와 시작 방법은 [한국어 README](../README.ko.md) 또는 [English README](../README.md)를 참고하세요.

## 구현 요약

Claude Code를 대상으로 작업 분석부터 모델 선택, 실패 시 승격, 로컬 사용량 집계까지 연결되어 있습니다. 사용량 CLI와 벤치마크 실행기, HTML 보고서, 선택적 PNG 캡처, 증거 파일 검증도 구현되어 있습니다. 기본 실행 모드는 관측이며, 자동 작업 분해와 Codex 실행기는 아직 연결되지 않았습니다.

| 구성 요소 | 완료된 내용 | 주요 구현 위치 |
| --- | --- | --- |
| 작업 분석 | 한국어·영어 규칙, 작업 유형·등급·신뢰도, 범위·위험·후속 요청 신호 | [analyzer.ts](../packages/core/src/analyzer.ts) |
| 모델 카탈로그 | 모델 식별, 계열별 상대 등급, 등급별 기본값, 비용 추정용 가격표 | [catalog.ts](../packages/core/src/catalog.ts) |
| 라우팅 정책 | `observe`/`route`, 모델·추론 강도 전략, 신뢰도 기준, 문맥 크기 보호 | [router.ts](../packages/core/src/router.ts) |
| 검증 및 승격 | 검증 명령 인식, 연속 실패 추적, 성공 시 초기화, 턴별 승격 한도 | [escalation.ts](../packages/core/src/escalation.ts) |
| 작업 브리프 | 목표·입력·수정 범위·의존성·완료 조건, 쓰기 충돌 검사, 실행 가능한 작업 조회 | [context.ts](../packages/core/src/context.ts) |
| 사용량 집계 | 요청·턴·서브에이전트 기록 타입, 토큰 집계, 비용 추정, 텍스트 보고서 | [usage.ts](../packages/core/src/usage.ts) |
| Claude Code 연결 | 세션·턴·도구·서브에이전트 훅, 상태 표시, `/router`, `/router explain` | [register.ts](../packages/claude-adapter/src/register.ts) |

| CLI | `report`, `explain`, `doctor`, `bench validate/run/report/verify` | [cli.ts](../packages/cli/src/cli.ts) |
| 보고서 | 사용량·벤치마크 HTML 보고서, 브라우저를 통한 전체 페이지 PNG 캡처 | [html/](../packages/cli/src/html), [capture.ts](../packages/cli/src/capture.ts) |
| 배포 기반 | npm 워크스페이스, 플러그인 번들 빌드, 마켓플레이스 매니페스트, CI 설정 | [package.json](../package.json), [build.mjs](../scripts/build.mjs), [ci.yml](../.github/workflows/ci.yml) |

작업 브리프 유틸리티는 라이브러리 수준에서 사용할 수 있습니다. 사용자의 큰 요청을 자동으로 분해하고 작업자를 실행하는 전체 흐름은 아직 구현되어 있지 않습니다.

## 벤치마크 구현

[실행기](../packages/cli/src/bench/run.ts)는 작업과 비교 조건마다 임시 프로젝트를 만들고, 모델 실행 이후 별도 검증을 수행합니다. 원시 기록에서 결과를 계산하고, 보고서와 증거 파일 목록을 생성합니다.

| 영역 | 구현 내용 |
| --- | --- |
| 작업 검증 | 원본 프로젝트에서는 실패하고 기준 해답을 적용하면 통과하는지 확인 |
| 실행 조건 | 작업·비교 조건 선택, 반복 횟수, 개별 실행 예산, 시간 제한, Claude 실행 파일 경로 지정 |
| 실행 방식 | 실제 `claude -p` 호출 또는 모델을 호출하지 않는 시뮬레이션 |
| 결과 판정 | 테스트·응답 내용 확인, 시간 초과·결과 누락·라우팅 로그 누락에 따른 무효 처리 |
| 집계 | 성공률, 성공당 비용, 시간, 토큰, 승격, 변경 줄 수, 분류 정확도, 비용 교차 비교 |
| 증거 검증 | SHA-256 파일 목록 확인, 원시 기록에서 개별 결과와 전체 집계 재계산 |

[예제 작업 6개](../examples/shop/tasks.json)는 다음 범위를 다룹니다.

| 작업 ID | 내용 | 기대 등급 |
| --- | --- | --- |
| `find-tax-rate` | 한국 세율이 정의된 파일 찾기 | `light` |
| `fix-receipt-typo` | 영수증 합계 라벨 오타 수정 | `light` |
| `rename-calc-total` | 프로젝트와 테스트 전체의 함수 이름 변경 | `standard` |
| `add-remove-item` | 원본을 변경하지 않는 장바구니 항목 삭제 기능 | `standard` |
| `fix-coupon-bug` | 쿠폰 적용 시 주문 금액 오류 수정 | `standard` |
| `tax-rule-registry` | 지역별 세금 규칙 등록 구조와 일본 세금의 정수 단위 내림 구현 | `heavy` |

[비교 조건](../benchmarks/arms.json)은 Opus 고정, Sonnet 고정, 자동 라우팅입니다. 자동 라우팅 조건은 표준 등급을 `sonnet`으로 지정합니다. 일반 플러그인의 표준 등급 기본값인 세션 모델 유지와는 설정이 다릅니다.

시뮬레이션은 가상의 토큰·비용·시간을 사용하고 모델 등급과 기대 등급에 따라 성공을 정합니다. 따라서 시뮬레이션 통과는 실행·집계·검증 흐름에 대한 확인이며, 실제 모델의 성공률이나 비용 절감률 측정이 아닙니다.

## 검증 결과

문서 작성 시 로컬 환경은 Windows, Node.js `v24.16.0`, npm `11.13.0`입니다.

| 검사 | 확인 결과 | 범위 |
| --- | --- | --- |
| `npm run check` | 통과 | 코어·코어 테스트·CLI 타입 검사, 단위 테스트, 플러그인 번들 일치 |
| 단위 테스트 | **88개 통과, 실패 0개** | 코어 76개, 벤치마크 파싱·판정·집계 12개 |
| `npm run build` | 통과 | Claude Code 플러그인과 CLI 번들 생성 |
| CLI `--help` 및 `explain` | 확인 | 명령 목록, 영어 이름 변경·한국어 오타 수정 예제 분류 |
| 기존 시뮬레이션 `bench verify` | **18회분 검증 통과** | 증거 파일·보고서 해시와 원시 기록 기반 결과·집계 일치 |
| Claude Code 엔진 검사 | 이번 문서 작업에서는 재실행하지 않음 | 현재 셸의 PATH에서 `claude`를 찾을 수 없음. 기존 문서에는 2.1.312에서의 통합 테스트 통과 기록이 있음 |
| 실제 모델 벤치마크 | 이번 검증에 포함되지 않음 | 실측 성능·비용 절감 결론 없음 |

검증한 기존 시뮬레이션의 식별 정보입니다.

```text
Run ID: 20261030-083835-simulated
Runs: 6 tasks × 3 arms × 1 repetition = 18
Data SHA-256: 1ea59baba19830bfc1f8b0124a634bd29da0c9d8eb619969037ad86887180711
```

해당 로컬 폴더에는 `run.json`, `results.json`, `report.html`, `report.png`, 증거 해시 목록이 존재했습니다. `run.json`에는 6개 작업 모두 원본에서 검증 실패·기준 해답에서 통과한 것으로 기록되어 있습니다. 시뮬레이션 폴더는 Git 제외 대상이므로 저장소 복제본에 포함된 배포 산출물로 취급하지 않습니다.

## 기록과 공유 범위

일상적인 플러그인 사용량 로그는 프롬프트나 소스 코드를 저장하지 않습니다. 반면 재현을 위한 벤치마크 실행 폴더는 `prompt.txt`, 모델 출력, 코드 패치, 검증 출력, 실행 설정을 보관합니다. 두 기록의 범위를 구분해 공유할 파일을 선택해야 합니다.

이후 구현이 달라지면 이 문서의 기준일과 검증 결과를 갱신하고, 사용자에게 보이는 변경은 [CHANGELOG](../CHANGELOG.md)에 반영합니다.
